# AgentRewardBench: evidence audit and pair predeclaration

This document is the Gate 1 record for the first **real** paired-evaluator evidence this
repository has held. Everything before it — `data/judge_runs_*.yaml`,
`data/SYNTHETIC_paired_runs.yaml` — was generated by `scripts/make_fixtures.py` and is
marked as such. Nothing here was generated.

It exists to be read *before* the paired analysis, and it was committed before the
analysis was run. The reason is narrow and it is the only reason: with 36 candidate
evaluator pairs available on the same 1,106 cases, a pair chosen after seeing its
complementarity is not evidence about complementarity. It is evidence about the
selection. So the audit below deliberately stops short of the joint 2×2 — the statistic
that would tell us which pair looks interesting is the one statistic
`scripts/arb_gate1.py` does not compute.

## 2. Reference labels: reused, not invented

The brief's constraint was that if AgentRewardBench already defines a label-resolution
rule we adopt it, and if it does not we stop and report the ambiguity rather than quietly
inventing one. It does define one, and two independent places in the upstream repository
agree on it:

- `agent_reward_bench/judge/utils.py:infer_annotator_type` marks the **first** CSV row
  for a `(benchmark, model_name, task_id)` triple `primary` and any later row
  `secondary`.
- `scripts/score_judgments.py` filters `annotator == "primary"` for all scoring.

So the second annotation is an inter-annotator-agreement *measurement*, never an
adjudication. There is no vote, no tie-break, and no consensus step to reproduce — the
primary annotator's label **is** the reference label. `Unsure` is dropped rather than
coerced. `scripts/arb_extract.py` transcribes this rule and the four distinct verdict
parsers (`functional` → `cum_reward > 0.5`; `aer`/`aerv` → the `Status:` line; `nnetnav`
→ the `Reward:` Likert-5 binarised at `>= 4`; everything else → the `<success>` tag).

**The transcription is verified, not asserted.** Re-scoring the nine judges in upstream's
own polarity (positive class = success) on the test split reproduces the paper's
published per-judge precision and recall exactly, to the single decimal place the paper
prints, for all eight judges it reports:

| judge | ours (P/R) | published (P/R) |
| --- | --- | --- |
| AER-C | 67.7 / 71.9 | 67.7 / 71.9 |
| NNetNav | 52.5 / 82.4 | 52.5 / 82.4 |
| Functional | 83.8 / 55.9 | 83.8 / 55.9 |
| GPT-4o (Axtree) | 69.8 / 83.1 | 69.8 / 83.1 |
| GPT-4o Mini (Axtree) | 61.5 / 86.1 | 61.5 / 86.1 |
| Claude 3.7 Sonnet (Axtree) | 68.8 / 81.6 | 68.8 / 81.6 |
| Llama 3.3 (Axtree) | 67.7 / 79.0 | 67.7 / 79.0 |
| Qwen2.5-VL (Axtree) | 64.3 / 89.8 | 64.3 / 89.8 |

One deliberate divergence, recorded because it is a divergence and not a bug. Upstream
maps an unparseable or `n/a` judgment to `-1`, which then scores as a *wrong* prediction.
Here a judgment that cannot be parsed stays **missing**: it is dropped from the pair, not
counted as an error. Six such judgments exist for `claude-3.7-sonnet-noscreen` and one
for `gpt-4o-mini-noscreen`, out of 1,106 each — small enough not to move the table above,
large enough that the denominators in section 3 are not all identical.

### Polarity

Upstream's positive class is success. Our failure mode is "the trajectory did not
achieve the goal", so **our positive class is the failure**. The inversion is stated once
in `scripts/arb_gate1.py` and applied there; it is not re-derived downstream.

## 3. Evaluation population, fixed before any pair was inspected

Test split, primary annotator, reference label not `Unsure`:

**1,106 trajectories — 811 reference-failure, 295 reference-success.**

By benchmark slice: `assistantbench` 108, `visualwebarena` 276, `webarena` 310,
`workarena` 412. Four agents under test (Claude 3.7 Sonnet, GPT-4o, Llama 3.3,
Qwen2.5-VL) are crossed with the benchmarks; the trajectories are real agent runs, not
constructed failures.

Wider context: `annotations.csv` holds 1,408 rows → 1,302 primary + 106 secondary.
`splits.csv` covers 351 tasks → 300 test, 51 dev. All nine fetched judges have complete
coverage of all 1,302 annotated trajectories; there are no ragged joins.

**No label contamination.** Six human experts annotated through a purpose-built UI. No
judge saw a reference label and no judge helped set one. This is the property that makes
the corpus usable for our question at all, and it is the property the nearest alternative
corpus (ATFD) does not have — see section 7.

## 4. The candidate set

Nine judges → 36 pairs, tabulated in `data/REAL_arb_gate1_candidate_pairs.csv`
(8 `HIGH`, 11 `MEDIUM`, 16 `LOW-MEDIUM`, 1 `LOW` on the independence rating below). Four
columns are constant across all 36 and are stated here once instead of 36 times:

- **cases with valid expert labels** = cases with both judgments (the reference label is
  present for every case either judge scored; the join never loses labels, only verdicts)
- **label contamination**: none, for the reason in section 3
- **latency**: `UNMEASURED` for every judge. `trajectory_info.summary_info.stats.cum_agent_elapsed`
  is the *agent's* elapsed time. Upstream records no judge timing at all, so no
  latency-aware conclusion is available from this corpus and none will be manufactured.
- **repeated judgments**: 1. `completion_args` is `{max_completion_tokens: 1024,
  temperature: 0.0, seed: 0}` and there is exactly one judgment per (case, judge).

Cost is not constant and has **three** states that must not be collapsed into two:
measured USD (`cost.total_price`, for OpenAI- and OpenRouter-hosted judges); structurally
absent (`functional` has a scalar `cost: 0` because there is no model call); and
**unpriced** — vllm-hosted judges (`nnetnav`, `llama-3.3-70b-noscreen`,
`qwen-2.5-vl-noscreen`) record `total_price: 0.0`, which means self-hosted and never
priced, not free. Treating the third as the second would invent a cost advantage out of a
missing measurement, so it is carried as `UNMEASURED (self-hosted)`. Token counts are
preserved separately and are not converted into money.

### Why these nine judges

The judgments tree is 3,740 MB, of which roughly 2,600 MB is base64 screenshot payload
embedded in `chat_messages` for six screenshot-input variants. Those six were not
fetched. The nine that were still cover **every distinct backbone** (gpt-4o,
gpt-4o-mini, claude-3.7-sonnet, qwen-2.5-vl, llama-3.3-70b) and **every distinct prompt
lineage** (AER, NNetNav, this paper's simplified template, programmatic), and each of the
six omitted is a same-backbone same-prompt sibling of a judge that is present — the kind
of pair the independence column rates LOW regardless. Recorded as a pre-outcome decision
so that a narrower candidate set cannot later be mistaken for the residue of shopping.

### Independence is a prompt-lineage question, not a data question

Nothing in the cached judgments reveals whether two judges share a prompt. That comes
from the paper (sec. 4.1) and `agent_reward_bench/judge/args.py`, and it is the fact that
decides whether a disagreement between two judges is informative or is an artefact of a
shared component:

- `functional` is a programmatic benchmark verifier: no model, no prompt, and a different
  input channel (environment state). Maximal independence from every LLM judge — rated
  `HIGH`.
- `aer`/`aerv` (Pan et al. 2024) and `nnetnav` (Murty et al. 2025) are prompts authored
  in **prior** work. They share nothing with this paper's template.
- The other ten judges all share one prompt template (paper Figures 5–6) and differ only
  in backbone and input modality. Two of them differing only in `use_screenshot` is rated
  `LOW`; sharing a template or a backbone but not both is `LOW-MEDIUM`.

## 5. The predeclaration

Selected on the five pre-outcome criteria only — adequate paired support, meaningful
evaluator independence, relevance to the stochastic-judge question, coverage across real
agent trajectories, provenance clarity. Support is adequate everywhere: the smallest
marginal error count across all 36 pairs is 153, against a presentation floor of 16
errors (25% relative standard error), so no pair is disqualified on support and support
therefore did not select anything. Coverage and provenance are likewise uniform. The
discriminating criteria are independence and cost measurability.

### Tier A — primary analysis: primary `functional`, alternate `aer`

n = 1,106 paired cases, 0 dropped, all four slices, 811/295 reference split.
Primary errors 162, alternate errors 184.

Chosen because it is the only construction that is independent on *both* axes at once:
`functional` shares no model and no prompt with any LLM judge, and `aer`'s prompt comes
from prior work rather than this paper's template, so the pair does not share a prompt
lineage with each other *or* with the bulk of the candidate set. It is also the only
`HIGH`-independence pair in which both cost states are knowable: the primary is
structurally free (no model call) and the alternate is measured USD. In the other seven
`HIGH` pairs the alternate is either vllm-hosted and unpriced, or shares this paper's
template, or both.

Direction — `functional` as primary rather than as alternate — is set by the shape of the
escalation question, not by either judge's error profile: a detector with zero marginal
cost is the one you run on everything, and the paid judge is the one you escalate *to*.
Reversing it would describe a deployment nobody would build.

### Tier B — stochastic arm: primary `aer`, alternate `nnetnav`

n = 1,106 paired cases, 0 dropped. Primary errors 184, alternate errors 272.

Tier A has a real limitation that Tier B exists to cover: `functional` is deterministic,
so Tier A answers "can a stochastic judge recover the misses of a deterministic
verifier" and cannot speak to the two-stochastic-judges case at all. `aer` × `nnetnav` is
the most independent stochastic pair available — different backbone (gpt-4o vs
Llama-3.3-70B-Instruct) *and* different prompt lineage (Pan et al. 2024 vs Murty et al.
2025), the only `MEDIUM` pair where both prompts are externally authored. Its cost
asymmetry is unrecoverable (measured USD against `UNMEASURED (self-hosted)`), so **no
cost-aware statement may be drawn from this arm** — it is there for the complementarity
structure and nothing else.

### Tier C — secondary, reported alongside

The remaining seven `functional` × LLM-judge pairs (`aer` excepted, being Tier A):
`aerv` is absent from the candidate set, so these are `claude-3.7-sonnet-noscreen`,
`gpt-4o-noscreen`, `gpt-4o-mini-noscreen`, `gpt-4o-mini-noscreen-noaxtree`,
`llama-3.3-70b-noscreen`, `nnetnav`, `qwen-2.5-vl-noscreen`. All rated `HIGH` — these are
every `HIGH` pair that exists. Reported in full, not to add power, but because reporting
eight pairs where Tier A is one of eight is the only way a reader can check that Tier A
was not the flattering one. If Tier A turns out to be an outlier among them, that is a
finding about Tier A.

### Excluded, and why

Twenty-seven of the 36: the 1 `LOW` pair, the 16 `LOW-MEDIUM` pairs, and 10 of the 11
`MEDIUM` pairs (Tier B being the eleventh).

The `LOW` and `LOW-MEDIUM` exclusions are on attributability. A disagreement between two
judges that share a backbone, or share a prompt template, is partly an artefact of the
shared component; the complementarity it appears to show cannot be assigned to
independent evidence. The 10 `MEDIUM` exclusions are weaker — those pairs are legitimate,
and any of them would have been defensible as Tier B. Tier B was picked from among them
on the single stated ground that it is the only `MEDIUM` pair where *both* prompts are
externally authored. That is a thin margin and it is recorded as thin.

All 36 sit in the committed table with their ratings, so every exclusion is auditable
against a rule that was stated before the outcomes were computed rather than fitted to
them.

## 6. What this evidence cannot answer

Stated here rather than at the end of the analysis, because a limitation discovered after
a result tends to get written as a caveat instead of as a constraint on the question.

- **Not stochastic noise.** Every judgment is single-shot at `temperature: 0.0, seed: 0`.
  This corpus can measure paired correctness and complementarity. It measures *nothing*
  about same-input repeatability. Variation between cases is not variation between
  repeats, and no repeatability number may be inferred from it. A repetition study needs
  fresh API calls that have not been made.
- **No latency, for any judge.** Not "approximately zero" — absent.
- **No cost for three of the nine judges**, for the reason in section 4. Historical API
  prices will not be backfilled to close the gap.
- **One failure mode.** Trajectory success is the clean binary endpoint. Side effects and
  looping are recorded upstream but are not used here.
- **Benchmark populations, not deployment traffic.** These are four agent benchmarks. The
  reference-failure rate of 811/1,106 is a property of how hard those benchmarks are for
  those four agents, not a base rate anyone should plan against. Every statistic that
  depends on prevalence inherits that.
- **Descriptive only.** Absent a declared economic scenario there is no break-even
  recovery `r*` to compare against, and none will be invented to create one. `r*` is a
  policy input on the same footing as `--max-error`.

## 7. Provenance wrinkles found, and not smoothed over

- **Six double annotations outside the described subset.** The paper describes a second
  annotator on a specific subset for agreement measurement. Six trajectories are doubly
  annotated outside it (three Qwen/webarena, three Llama/workarena). They change no
  reference label — the primary rule resolves them — but the paper's account of which
  cases were double-annotated is not exactly the file's.
- **The IAA figure reproduces.** 89/100 agreement on webarena/GPT-4o against the paper's
  89.3%, which is the check that confirms the primary/secondary rule was read correctly
  rather than merely plausibly.
- **One stray `aerv` judgment** sits in the local cache from an earlier structural
  inspection, giving that judge 1 case of coverage against 1,302. `arb_extract.py` now
  prints per-judge coverage and flags partials, and `arb_gate1.py` restricts candidates
  to an explicit allow-list, because a judge with full provenance and two cases of
  support is exactly the sort of thing that enters an audit table looking respectable.
- **ATFD (`Galea-foo/atfd` @ `690c9962155865b3b17333bbb9354c15d3eb4170`, CC BY 4.0)** was
  assessed as prior art and is *not* a substitute for this corpus: its ground truth is
  majority-voted over LLM annotators (`JUDGE_MODELS = ["gpt-4.1", "claude-sonnet-4",
  "llama-4-scout"]`) that are themselves among the evaluated systems, and the
  2,577-trajectory corpus behind its headline table is not published. It does
  genuinely overlap our instrument on Wilson and bootstrap intervals, DR/FPR/F1, Fleiss'
  κ, and per-trajectory cost with token counts and latency; McNemar's paired test is the
  nearest prior art to our paired work, though it answers "is one better" rather than
  "can the alternate recover the primary's misses". Two documentation conflicts follow
  from this section and from section 3, and are recorded rather than acted on here:
  `docs/architecture.md`'s claim that nobody has per-evaluator sensitivity and FPR needs
  narrowing, and §10.1's prior-work list is missing evaluator-benchmarking-against-human-
  labels-with-cost-accounting. Both are held until the analysis lands so the correction
  arrives with its evidence.
