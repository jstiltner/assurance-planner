# Alternate-source collection protocol

Written before any alternate-source data exists, and committed so the bar cannot move once
results are in. Two shipped code paths cite this file by name — the refusal in
`AlternateCharacteristics.expected_error_rates()` and the shortfall section of
`characterize-alternate` — because both of them are telling a reader that the thing they
wanted to read has not been collected yet, and both owe them the recipe.

## 0. Why this document exists at all

[`experiment_red_team.md`](experiment_red_team.md) argued that the repetition study was the
wrong next action, and that the cheapest open question was the alternate source's real
sensitivity and false-positive rate — "one pass of a second evaluator over an
already-labelled set".

**That claim was wrong, and the error is worth stating plainly because it is the finding
that shapes everything below.** There is no second evaluator and there is no labelled set.
Every case in `data/` was generated by `scripts/make_fixtures.py` from a seeded
`random.Random`; the labels are the generator's inputs, not anyone's judgment. The two
numbers the planner had been pricing escalation from — sensitivity 0.95, false-positive
rate 0.05 — were float literals with no study behind them.

So this is not a measurement that can be scheduled for an afternoon. It is a
data-collection project, and its cost is dominated by a fact established in §6: the
denominator for the only statistic that matters is *primary errors*, not cases.

The instrument that will read this data already exists and is tested
(`complementarity.py`, `complementarity_report.py`, `characterize-alternate`). Nothing in
it needs to be built when the data arrives. What follows is the input specification.

---

## 1. What constitutes the alternate source

An alternate source is admissible only if it is **a different way of being wrong**, not a
more expensive way of being wrong identically. The instrument can measure that
(`error_association_phi`), but the study is wasted if the answer was predictable in
advance.

Required, all four:

1. **Named and versioned.** A `source_id@version` recorded in the run header as
   `alternate_version`. The loader refuses observations from an unnamed source, because an
   unattributed verdict cannot be keyed to a qualification slot.
2. **Independently re-runnable.** Someone other than the author must be able to obtain a
   verdict on a new case from the same source at the same version. A one-off human pass
   with no written rubric fails this: the version is not a version.
3. **Not derived from the primary.** A source that reads the primary's verdict, its score,
   or its reasoning before deciding is not an alternate source. Its errors are conditioned
   on the primary's and phi will be inflated by construction. If the candidate is "the same
   judge with a better prompt", that is a *new primary version*, and it belongs in
   `characterize-evaluator` against the existing primary as a baseline — not here.
4. **Plausibly differently wrong, stated in advance.** Write down, before collection, the
   mechanism by which this source should succeed where the primary fails. "It is a larger
   model" is not a mechanism. "It reads the full transcript rather than the final turn, and
   the primary's failures are concentrated in cases where the relevant content is not in
   the final turn" is.

Explicitly admissible candidates: a human reviewer working from a written rubric; a
different model family; the same family with materially different input (full transcript,
retrieved context, tool traces); a deterministic checker with no model in it.

If the alternate is a human panel, the panel *is* the source and its members are its
stochasticity (§4). Do not record a single reviewer's verdict as "the human baseline".

## 2. What cases must be run through it

**The same cases, all of them.** `paired_errors` counts only cases with a decided verdict
on both sides; anything else lands in `unpaired` and is excluded rather than assumed to
agree. An alternate sensitivity computed over a different case set than the primary's
cannot be differenced against it, and the difference is the first thing anyone computes.

Rules:

- **Do not select cases by primary outcome.** Running the alternate only on cases the
  primary got wrong makes `P(alternate correct | primary wrong)` estimable and
  `P(primary correct | alternate wrong)` un-estimable, destroys both marginals, and makes
  the alternate's standalone sensitivity unmeasurable — which is exactly the number needed
  to answer "replace the primary". If budget forces subsampling, subsample **at random with
  a recorded seed and a recorded sampling rate**, never by outcome.
- **Do not add cases for the alternate that the primary never saw.** They will be dropped.
- **Record non-coverage explicitly.** A case not sent to the alternate keeps an empty
  `alternate_observations` list. Absence is a value; do not backfill it.
- **Every slice, or say which are missing.** Per-slice complementarity is where a routing
  rule would have to live, and a slice with no alternate coverage cannot be routed.

## 3. How reference labels must be established

This is the part with no shortcut, and it is the reason the project has no data.

- **Labels must come from neither source.** A reference label derived from the primary
  makes the primary correct by definition. A label derived from the alternate does the
  same in the other direction and will manufacture complementarity.
- **Labels must be fixed before either source runs**, or at minimum before either
  source's output is visible to the labeller. Record the date.
- **The failure-mode definition is part of the label.** Labels are keyed to
  `failure_mode@version`. If the definition is edited, the labels are labels for a
  different question and the version must be bumped; the instrument will then refuse to
  read the old artifact into the new slot.
- **Two independent labellers on at least a subset, with agreement reported.** If the
  humans defining truth disagree at rate *r*, no source can be measured to better than
  *r*, and a complementarity difference smaller than *r* is not a finding. Report the
  labeller agreement rate alongside the results; if it is not reported, assume it was
  not measured.
- **Adjudication procedure written down in advance**, including what happens to cases the
  labellers cannot resolve. Those cases are **excluded and counted**, not assigned to the
  majority.
- **No label may be revised after seeing either source's verdict.** If a source's output
  reveals a genuinely mislabelled case, the correct action is to fix the label, record the
  revision and the reason, and re-report both sources against the corrected set — not to
  quietly correct the cases where the favoured source lost.

## 4. Repeated observations, if the alternate is stochastic

Assume it is until shown otherwise. A single observation cannot distinguish "wrong" from
"wrong this time".

- **Minimum 3 observations per case**, 5 preferred. Ties are possible at even counts and
  are discarded as undecided by the same rule applied to the primary; prefer odd counts.
- **Independent observations.** Fresh context each time. A cached response repeated three
  times records a within-case disagreement of 0 and will make the source look
  deterministic.
- **Report within-case disagreement.** `characterize-alternate` prints mean same-case
  agreement and the count of inconsistently-answered cases. If it is materially non-zero,
  the alternate is itself a stochastic evaluator and the same repetition-versus-escalation
  question applies recursively to it.
- **If the source is deterministic, demonstrate it** with 2 observations on every case
  rather than asserting it. A deterministic checker costs almost nothing to run twice.
- **Repetition reduces stochastic uncertainty; it cannot repair systematic error.** A case
  the alternate answers wrong unanimously stays wrong at any *n*. The per-case
  `repetition_verdict` field exists to separate the two, and the cases repetition cannot
  fix are the ones that decide whether escalation is worth anything.

## 5. Cost and latency fields

Capture per observation, on both sides, in the long observation form:

| field | unit | notes |
|---|---|---|
| `cost` | USD | actual billed or actual labour cost for *this* observation |
| `latency_ms` | milliseconds | wall clock, including queueing and human turnaround |

Rules:

- **All-or-none per case.** The loader refuses partial annotation, because a mean over half
  the observations is not a mean over the observations.
- **The short bitstring form cannot carry economics** and is for synthetic fixtures only.
  Real collection uses the long form.
- **Unknown stays unknown.** If billing data is unavailable, omit the field and let the
  report print `UNMEASURED`. Do not substitute a list price, a token estimate, or the
  placeholder in `CostModel`. An empty cell prompts someone to collect the number; a
  fabricated one does not.
- **Human latency is wall clock, not effort.** A reviewer who returns a verdict in two days
  has a two-day latency even if the work took four minutes. Escalation latency is what
  makes escalation expensive; recording effort instead would hide the entire cost.
- **Record the currency and date if labour cost is converted**, and record fixed setup cost
  separately from per-observation cost.

## 6. Minimum sample size and slice support

The governing arithmetic, and the reason this study is not cheap:

> The denominator of `P(alternate correct | primary wrong)` is **primary errors**, not
> cases. An accurate primary makes complementarity *more* expensive to measure, not less.

`MIN_ERRORS_FOR_CONDITIONAL = 16` is derived, not chosen: to place a Wilson interval
against 0.5 at all requires 16 errors even at an optimistic observed recovery rate of 0.75
(12/16 gives [0.505, 0.898]; 9/12 gives [0.468, 0.911] and cannot). At less flattering
recovery rates the requirement grows sharply:

| true recovery rate | primary errors needed |
|---|---|
| 0.90 | 4 |
| 0.80 | 11 |
| 0.75 | 16 |
| 0.70 | 21 |
| 0.60 | 91 |

Converting to cases via `required_paired_cases(primary_error_rate) = ceil(16 / rate)`:

| primary error rate | paired cases for 16 errors |
|---|---|
| 0.40 | 40 |
| 0.20 | 80 |
| 0.10 | 160 |
| 0.05 | 320 |

Floors:

- **`MIN_PAIRED_CASES = 40` decided pairs** before any overall figure is quoted, matching
  the existing `MIN_CASES_FOR_COMPARISON`.
- **16 primary errors** before any conditional is quoted. Below it the report prints the
  point estimate and interval but marks the conditional unsupported, and
  `characterize-alternate` exits non-zero.
- **Replacement vs complementarity needs both marginals**, each on ≥40 pairs: replacement
  is a claim about the alternate's standalone sensitivity and FPR, complementarity is a
  claim about the off-diagonal. A study powered for one is not powered for the other.
- **Per slice, the same two floors apply**: the instrument flags any slice under 40 decided
  pairs as thin and any slice conditional under 16 errors as unsupported. This is the
  expensive line and it is not negotiable if a routing rule is the goal — a routing rule is
  a per-slice claim, and a per-slice claim on 12 cases is not a claim. Three slices is 120
  pairs *and* needs 16 primary errors inside each one, which an even split will not
  produce. (§2.2 of [`real_experiment_protocol.md`](real_experiment_protocol.md) derives a
  separate per-slice floor of ~30 for placing a slice's stable-wrong rate against 0.30.
  That is a different question with a different denominator; satisfying it does not satisfy
  this one.)
- **If the primary is accurate and the budget is fixed, the honest outcome is that
  complementarity is unmeasurable at this scale.** Report that. It is a real answer and it
  argues against the routing feature, which is the point.

## 7. What must remain held out if a routing selector is later designed

No selector is being built now. When one is, these constraints bind, and they bind because
the instrument cannot detect their violation after the fact:

1. **A held-out set fixed and sealed before any threshold is examined**, by a recorded
   split seed. Not a fold assigned after the numbers were seen.
2. **Nothing in the held-out set may inform the selector**: not thresholds, not slice
   definitions, not which slices exist, not feature selection, not the decision to
   re-run collection.
3. **Slice definitions are part of the model.** Redrawing slice boundaries after seeing
   per-slice recovery rates is threshold tuning with extra steps, and it is the most
   likely way this project fools itself.
4. **One evaluation on the held-out set, reported whatever it says.** A second look makes
   it a validation set and it must then be replaced with fresh data.
5. **A blind-escalation control and a primary-only early-stopping control are evaluated on
   the same held-out set.** The candidate must beat both. The existing synthetic benchmark
   already shows blind escalation dominating the candidate policy on one fixture, so this
   is not a formality.
6. **Held-out cases must be paired too.** A held-out set the alternate never saw cannot
   evaluate a policy that escalates to the alternate.
7. **Per-slice held-out support must be sized in advance** (§6). The common failure is a
   held-out cell containing two cases.

---

## 8. What the instrument will and will not tell you

It computes the 2x2, both conditionals with Wilson intervals, the joint error rate, both
shared-error fractions, verdict disagreement, Pearson phi on the error association, and
per-slice versions of all of it with support flags.

It emits **no verdict.** Every cell of the decision table reads `UNMEASURED` and there is
no code path that writes anything else into one. Replacement, selective routing, and
rejection are conclusions for a human to draw from a real artifact, against criteria fixed
before the data is seen — which is what §§1–7 are for.

The synthetic paired fixture (`data/SYNTHETIC_paired_runs.yaml`) exists only to exercise
that arithmetic on input whose structure is known. Its artifact can be written and
inspected but never loaded as planner evidence, and its numbers are statements about a
seeded random number generator.
